# 微信小程序订单功能修复说明

## 问题诊断

1. **订单列表显示虚拟订单**
   - 原因：调用 `/cleaning/orders` API时未传递 userId 参数，导致查询失败
   - 后备方案加载了模拟数据

2. **小程序下单流程没有真实创建订单**
   - 下单流程（create → stores → delivery → payment）完整，但缺少关键步骤：
   - 支付前没有调用 `POST /api/cleaning/orders` 创建真实订单
   - 导致订单数据没有同步到后端数据库

3. **C端和小程序数据不同步**
   - C端（网页）使用 `userId`（guest_xxx 或 localStorage中的ID）
   - 微信小程序使用 `openid`
   - 导致两边数据无法关联

## 修复内容

### 1. 修复小程序订单列表 ✅
**文件**: `wechat-mini-app/pages/orders/index.js`

修改内容：
- 传递 `userId` 参数（使用 openid）
- 修复数据结构处理逻辑（兼容数组和对象格式）
- API失败时只在没有订单时才加载模拟数据
- 添加详细日志便于调试

### 2. 完善小程序下单流程 ✅
**文件**: `wechat-mini-app/pages/order/payment/index.js`

新增功能：
```javascript
// 确认支付前，先创建真实订单
async createOrder() {
  // 准备订单数据
  const orderPayload = {
    userId: userInfo?.openid || userInfo?.id || 'guest_' + Date.now(),
    storeId: orderData.store?.storeId || 'ST001',
    items: orderData.services.map(service => ({
      name: service.name,
      price: service.price,
      quantity: 1,
      serviceType: 'dry_clean'
    })),
    deliveryMethod: orderData.deliveryMethod,
    delivery: { ... },
    amounts: { ... }
  };
  
  // 调用后端API创建订单
  const result = await app.request('/cleaning/orders', orderPayload, 'POST');
  return result;
}
```

### 3. 添加服务列表API ✅
**文件**: `backend/modules/cleaning/routes.js`

新增接口：
- `GET /api/cleaning/services` - 返回标准干洗服务列表

### 4. 修改小程序服务选择页面 ✅
**文件**: `wechat-mini-app/pages/order/create/index.js`

修改内容：
- 从后端API获取服务列表
- 添加默认服务列表作为后备方案
- 添加加载状态显示

### 5. 统一用户标识体系 ✅
**文件**: `backend/modules/cleaning/routes.js`

修改内容：
- 订单查询：同时支持 `userId` 和 `openid` 参数
- 订单创建：统一使用 `openid` 或 `userId`

```javascript
// 查询时
const queryUserId = userId || openid || req.user?.id;

// 创建时
const userId = req.body.openid || req.body.userId || req.user?.id;
```

## 注意事项

1. **用户标识一致性**
   - 如果C端和小程序要看到相同的订单，需要使用相同的用户标识
   - 建议：C端也改用openid（需要先完成微信授权登录）

2. **API地址配置**
   - 确保后端服务运行在 `192.168.1.8:3000`
   - 检查 `wechat-mini-app/app.js` 中的 `apiBaseUrl` 配置

3. **数据库连接**
   - 确认MongoDB服务正常运行
   - 检查后端日志中的数据库连接状态
